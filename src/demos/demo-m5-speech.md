## Иван - Архетиктура

> Слайд 4

Наша архетиктура поделена на 4 слоя:
1. User слой - слой, который по факту и является конечным пользователем, то есть браузер пользователя и почта пользователя.
2. Interface слой - слой, который отвечает за предоставление возможности взаимодействия пользователя с нашим приложением,
в него входит frontend и admin control.
3. Service - это уже слой, который пользователю недоступен, это слой в котором работает весь бекенд.
4. DataBase - слой базы данных.

User слой имеет: почту и браузер, как говорилось и как видно на схеме, через браузер используя UI пользователь имеет возможность
взаимодействия с приложением, а именно ко всему frontend и в случае, если пользователь - админ, имеет еще и доступ к admin control.
Если вернемся к почте, с почтой наше приложение взаимодействует через Backend через уведомления.

Interface слой имеет: frontend и admin control, как говорил ранее пользователь всегда имеет доступ к frontend, но только в случае,
если пользователь имеет права администратора, то имеет доступ к admin control.

Service слой: все модули слоя Interface по API эндпоинтам отправляют запросы непосредственно Backend, и в последующем на слой базы данных
при изменении данных.

## Иван - Технические детали

> Слайд 5

### Технический стек фронтенда:

- React + Vite
В качестве основы фронтенда использовался React — популярная библиотека для создания пользовательских интерфейсов. Для сборки проекта выбран Vite, который обеспечивает быстрый запуск приложения, мгновенную перезагрузку при разработке и оптимизированную сборку для продакшена.

- React Router DOM
Для организации навигации между страницами использовался React Router DOM. Он позволяет реализовать клиентскую маршрутизацию без полной перезагрузки страницы, что делает взаимодействие с приложением более плавным и быстрым.

- TanStack Query
Для работы с серверными данными применялся TanStack Query. Библиотека отвечает за получение, кэширование и обновление данных с API, снижая количество лишних запросов и упрощая управление состоянием данных.

- React Leaflet
Для отображения интерактивной карты использовалась React Leaflet — React-обёртка над библиотекой Leaflet. Она позволяет отображать карту, маркеры и другие географические объекты, обеспечивая удобную работу с геоданными.

- CSS Modules
Для стилизации компонентов применялись CSS Modules. Такой подход обеспечивает локальную область видимости стилей, предотвращает конфликты между классами и делает структуру проекта более поддерживаемой.

### Технический стек бекенда:

- Java 21
В качестве основного языка программирования использовалась Java 21 — современная LTS-версия платформы, которая обеспечивает высокую производительность, надежность и доступ к актуальным возможностям языка.

- Spring Boot
Основой серверной части является Spring Boot. Этот фреймворк упрощает разработку веб-приложений, предоставляет готовую инфраструктуру для создания REST API и позволяет быстро настраивать необходимые компоненты системы.

- PostgreSQL
Для хранения данных используется PostgreSQL — объектно-реляционная система управления базами данных с открытым исходным кодом. Она обеспечивает надежное хранение информации, поддержку сложных запросов и высокую устойчивость к нагрузкам.

Основные задачи Backend

- Серверная часть, реализованная на Spring Boot, отвечает за:
обработку HTTP-запросов через REST API;   
реализацию бизнес-логики приложения;   
взаимодействие с базой данных;   
обработку и валидацию данных перед их сохранением или передачей клиенту.   

- Роль PostgreSQL

PostgreSQL используется как основное хранилище данных и обеспечивает:
реляционную модель хранения данных;   
поддержку транзакций для безопасного выполнения операций;   
целостность и согласованность данных;   
надежное хранение и быстрый доступ к информации.

## Иван - Аналоги

> Слайд 6

На рынке уже существуют решения для поиска мероприятий, такие как Meetup, Eventbrite и разделы событий в Facebook Events. Однако большинство таких платформ ориентированы либо на крупные коммерческие мероприятия, либо на уже сформированные сообщества.

Наше приложение отличается тем, что делает акцент на локальных событиях и быстром поиске мероприятий рядом с пользователем. Основным интерфейсом является интерактивная карта, которая позволяет сразу увидеть доступные события по геолокации, а не просматривать длинные списки мероприятий.

В отличие от многих аналогов, у нас реализованы встроенные механизмы персонализации:
- фильтрация по категориям, тегам, времени и местоположению;
- возрастные ограничения для мероприятий;
- ограничение по количеству участников;
- сохранение событий, в которых пользователь участвует;
- уведомления о предстоящих мероприятиях.

Еще одним преимуществом является возможность создания собственных локальных событий буквально за несколько минут. Пользователь может самостоятельно указать место проведения на карте, настроить ограничения и сразу сделать мероприятие доступным для других участников.

С технической точки зрения наше решение также обладает рядом преимуществ. Мы используем современный стек технологий: React и Spring Boot обеспечивают высокую производительность и масштабируемость, а интеграция frontend и backend уже полностью реализована. Кроме того, проект покрыт тестами и имеет подготовленную архитектуру для дальнейшего развития функционала.

Таким образом, если такие платформы как Meetup или Eventbrite больше ориентированы на организацию крупных мероприятий и профессиональных сообществ, то наше приложение сфокусировано на создании локального сообщества города, удобном поиске событий поблизости и простом взаимодействии между пользователями. Это делает сервис более доступным для студентов, молодых специалистов и всех, кто хочет быстро находить интересные активности рядом с собой.

## Саша - Восстановление пароля

> 20 Слайд

Есть готовое восстановление пароля, когда в случае забывания пароля, пользователь может восстановить его и войти в аккаунт.   
Есть реализованные экран, и вся логика восстановления пароля.   
Пользователь нажимает на кнопку `Forgot password?`, вводит свою почту.   
На почту приходит код для восстановления пароля, пользователь вставляет этот код для восстановления в приложение и вводит новый пароль.
Бекенд сохраняет новый пароль вместо предыдущего учетной записи пользователя и пользователь может дальше пользоваться нашим приложением.   
Для завершения этой задачи осталось только совместить фронтенд и бекенд.
